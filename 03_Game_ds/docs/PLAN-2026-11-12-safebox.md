# 柜子（safebox）改造方案 v1 — 2026-11-12

> 状态：**待操作者确认后开工**（要改游戏侧，按 AGENTS §6.36 必须先点头）。
> 决策来源：操作者 2026-11-12 的四条口径（见 AGENTS §6.37）。

---

## 1. 目标

把柜子从「按尺寸算法排布」改成「**JSON 指定坐标的纯占位装饰**」：

- 位置、尺寸、`×N`、`Lv.N` 全部由数据决定，编辑器可视化配置
- 规则上仍然是「占格阻挡」，但不参与任何玩法（不可点、不可炸、不可化、无倒计时、无解锁）

---

## 2. 新 JSON 结构

```json
"levels": [
  {
    "id": "第一关",
    "safes": [
      { "size": "2x4", "slot": [1, 6], "charges": 10, "level": 22 },
      { "size": "1x7", "slot": [0, 8], "charges": 3,  "level": 12 },
      { "size": "2x2", "slot": [5, 4] }
    ]
  }
]
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `size` | string | ✅ | `1x7` / `2x2` / `2x3` / `2x4` |
| `slot` | `[x, y]` | ✅ | **左上角锚点**，整数格坐标 |
| `charges` | int | ❌ | 画成 `×N`；默认 `10`；要求 `≥1` |
| `level` | int | ❌ | 画成 `Lv.N`；默认 `22`；要求 `≥1` |

占位规则（由 `size` 推出，方向固定，不支持旋转）：

| size | 宽×高 |
|---|---|
| `1x7` | 7 × 1 |
| `2x2` | 2 × 2 |
| `2x3` | **3 × 2** |
| `2x4` | **4 × 2** |

**旧写法废弃**：`safes: ["2x4", "2x3"]`（字符串、位置靠算法）不再被游戏接受。
读到字符串条目 → 校验报错；编辑器打开旧数据时提供自动转换（见 §6）。

---

## 3. 校验规则（游戏 CLI 与编辑器必须一致）

对每个柜子：

1. `size` 必须在四种之内
2. `slot` 必须是两个整数，且 `x ≥ 0`、`y ≥ 0`
3. **越界**：`x + w > board.width` 或 `y + h > board.height` → 报错
   （例：`(0,8)` 放 `2x4`（4×2）在 7×9 棋盘上 → `x+4=4 ≤ 7` 但 `y+2=10 > 9` → **报错**）
4. **柜子互相重叠**：任意两个柜子的覆盖格交集非空 → 报错
5. **压到棋子/生成器**：任一覆盖格已有 `board.slots` 条目 → 报错
6. **压到障碍**：任一覆盖格已有 `lock/web/ice/bag` 障碍 → 报错
7. `charges` / `level` 若存在必须是 `≥1` 的整数

错误文案要能直接定位，例如：

```text
第一关：柜子 #2（2x4 @ (1,6)）超出棋盘：y+2=8 > 9
第一关：柜子 #1（2x4 @ (1,6)）与柜子 #3（2x2 @ (3,7)）重叠于 (3,7)
第一关：柜子 #1（2x4 @ (1,6)）压住了棋子 (2,7)
```

## 5. 数据兼容 / 迁移

- 游戏侧：只认对象写法；字符串条目 → 校验错误（不静默忽略，避免“柜子凭空消失”）
- 编辑器侧：读到字符串条目时，用**现有 JS 版 `Safeboxes.layout`**（保留在编辑器里，仅用于迁移）算一次坐标，
  转成对象写回，并提示「已转换 N 个柜子，记得保存」；转换后即可删除 `layout` 这份 JS 代码
- 老 take 不受影响（take 不记录柜子位置）

---

## 6. 编辑器（05_editor）改动

1. **类型下拉**加「柜子」
2. 选中柜子格时，右栏出现子选项：
   - 尺寸（1x7 / 2x2 / 2x3 / 2x4）
   - 锚点 `x` / `y`（两个数字框，**左上角语义**）
   - `×N`（charges）、`Lv.N`（level）
   - 删除该柜子
3. **放置**：类型=柜子 + 选尺寸 + 点棋盘某格 → 以该格为左上角放下；越界/重叠/压棋子时**当场报错并高亮冲突格**
4. **移动**：拖动柜子整体平移（锚点跟着变），落地时做同一套校验，非法则回弹
5. **复制**：Ctrl+拖 = 复制一个柜子（新锚点）
6. **预览**：按 `size` 画柜子底图 + 泡泡 + `×N` + `Lv.N`（复用现有素材 `safebox_*` / `bubble` / 字体）
7. 点柜子覆盖的**任意格**都能选中这个柜子（高亮整个柜体）

## 7. 验收标准

| # | 验收 | 方式 |
|---|---|---|
| 1 | 新结构能加载、能出片，柜子位置与 JSON 完全一致 | 自造工程 + `bash tools/render.sh` 抽帧比对 |
| 2 | 越界 / 重叠 / 压棋子 / 压障碍 四类错误都能报出来 | `t_safeboxes.gd` 反例 + 编辑器提示 |
| 3 | 柜子格仍然阻挡（不能落子/合并/拖动） | `t_sim`：向柜子格 `move/merge/drop` 都返回 `SIM_BLOCKED` |
| 4 | 爆炸不会破坏柜子 | `t_sim`：blast 前后 `safe` 障碍仍在 |
| 5 | 旧字符串写法被拒 | `validate --strict` 对反例工程报错 |
| 6 | 编辑器自测通过 | `bash 05_editor/selftest.sh` → `SELFTEST PASS` |

## 8. 风险 / 待确认

1. **越界判定口径**：本方案按“整个柜子必须完整落在棋盘内”执行（截断/裁剪不做）
2. `2x3`、`2x4` 的宽高方向固定（3 宽 2 高 / 4 宽 2 高），不做旋转
3. 是否允许柜子压在**柜子已占的格**上——本方案禁止（报错）
4. 编辑器里旧数据自动转换只在“打开工程”时执行一次，转换结果需要操作者保存
