### P1-2　`framemd5` 基线依赖"导入缓存状态"，同一 HEAD 有三种成片 hash

- **现象**：同一 commit、同一机器、同一命令，仅因 `.godot/imported` 缓存不同 → 3 种输出（各自双跑稳定）：

| 缓存状态 | framemd5 | mp4 sha256 | 字节 |
|---|---|---|---|
| 无缓存（纯净副本） | `4dc74c8168ab3bda…` | `361ce1088c7a71e1…` | 1,662,210 |
| 仅 M0 的 22 个缓存（作者当时态） | `6accae7c697c264c…` | `0acc8978e066f398…` | 1,662,023 |
| 编辑器导入后的全量缓存（当前工作区） | `f7f28fc8a10876f0…` | `08674e20f4ec800a…` | 1,627,209 |

- **根因**（systematic-debugging 四阶段已走完，变量逐个隔离）：
  1. 只加 `.import`（无 ctex）→ 与"无缓存"完全同 hash（`head_imp == head`），排除 `.import` 文本本身；
  2. 加 `.godot` 全量缓存 → 与工作区完全同 hash（`head_full == worktree`，连 mp4 都字节相同），锁定 **ctex 缓存存在性**为唯一变量；
  3. 只保留 22 个 M0 ctex → **精确复现作者 hash**，并解释作者态（44 张新图当时无 `.import`，走 `Image.load_from_file` 回退）。
  4. 机制：`game/asset_loader.gd` L106–152 的"有 ctex 走 `ResourceLoader`（CompressedTexture2D），否则运行时解码 ImageTexture"双路径。
- **视觉影响很小**：全缓存 vs 混合态 mean|Δ|=0.95/255、Δ>8 的像素 2.81%；全缓存 vs 无缓存 mean|Δ|=1.01、3.13%。**是 hash 级差异，不是观感级差异。**
- **影响**：报告/README 把 `6accae7c…`/`0acc8978…` 当"基线 hash"记录，但换机、换 clone、或任何人开过编辑器后都不复现；若 PK 以 framemd5 作为"同题不同实现"的对照量，必须先固定缓存态。
- **最小复现**：

```bash
# A 无缓存
git archive bcbf06a 02_Game | tar -x -C /tmp/A
bash /tmp/A/02_Game/tools/render.sh --project res://data/projects/sample_30s.json --out /tmp/A/pet.mp4
ffmpeg -v error -i /tmp/A/pet.mp4 -map 0:v -f framemd5 /tmp/A/md5 && sha256sum /tmp/A/md5
#   → 4dc74c8168ab3bda…

# B 全量缓存（把工作区 .godot 拷进副本）
cp -r 02_Game/.godot /tmp/A/02_Game/.godot && cp 02_Game/assets/*.png.import /tmp/A/02_Game/assets/
bash /tmp/A/02_Game/tools/render.sh ... --out /tmp/A/pet2.mp4
#   → f7f28fc8a10876f0…（= 当前工作区）
```

- **建议**（择一，均不动业务代码）：① 验收/记录基线时固定"无缓存"态（`rm -rf .godot` 后出片，hash 与机器无关）；② 把 `.import` 与 `.godot/imported` 一起纳入确定性口径并在 README C1 明写"开过编辑器 hash 会变"；③ 让 `AssetLoader` 对 2D 贴图统一走同一条解码路径（需改代码，属 M2）。
