## 5. 互证与分歧（对读要点）

1. **两条裁决是镜像关系**：03 已实现 merge kind + directOrder（DS03 报告"确认无问题"），02 未实现（CC02 报告 P1-1/P1-2）。这不是分歧，而是同一裁决在两条 lane 上的落实差。
2. **可达性算法方向相反、可互补**：02 的 `_check_order_reachability` 骨架（本关棋盘 + charges + 逐级合并容量）正是 03 重写 F1 该用的口径；03 的审查反过来发现 02 仍有 lock 障碍/共享 charges 的漏杀边界（P2-3）。两边都要按"合并闭包 + 容量推导 + 障碍约束"补齐。
3. **假绿类问题只在 03 侧被证实，但 02 也有同类风险**：02 的 `export_info` 同样不跑模拟、`render.sh` 同样不扫 SCRIPT ERROR（CC02 报告 P2-2）。建议两边统一加"出片前跑模拟 + rejected>0 即失败 + 扫描 SCRIPT ERROR"的门禁。
4. **测试规模不可直接横向比**（442 vs 953，套件粒度不同）；横向比的是验收结果与缺陷密度。
5. **共同的规格缺口**（详见 §6）不是任何一方单方面违反，不能当缺陷让实现者顺手改。
