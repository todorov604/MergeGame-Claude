## 目标

## 视觉目标（2026-11-05 追加）

画面（尤其背景）尽量贴近 `00_design/买量视频工具-需求框架.md` §20.5「棋盘.psd 结构」与参考图 `00_design/images/psd_slices/board_full_preview.jpg`（1080×1920）。版权无问题（公司自有）；除合成小 icon 使用我们的 chip 链外，布局与素材尽量一致：

- 背景：`main_bg_01_bottom`（1080×1536）铺底 + `main_bg_01_top`（1080×400）叠顶；
- 棋盘容器：`board_frame` 983×1263，位置 (48,466)；7×9 格，单格约 140×140；
- 顶栏 `money`（等级/能量/金币/宝石）、订单角色 `part1/part2`、底部 `items` 693×183 @ (193,1731)、左下退出/右下背包、特殊格/冻结/区域遮罩；
- 棋子：真实 icon 182×182 缩放到约 132–140，格内底边对齐、轻阴影；合成小 icon 与参考图不同是有意的。

验收：1080×1920 游戏画面截图与参考图并排对比，报告差异与缺失；不破坏原有 tests/strict/accept/确定性验收。

## 验收

- 真实图标样片/截图：chip 显示真实 icon 而非占位；
- 换一套主题（图标/配色）→ 出一条片，全程不改代码；
- 单条 30s 出片 ≤ 5 分钟；
- 双跑 framemd5 一致（抽查）；不同主题出片 framemd5 不同。

## 不做（当前目标）

批量调度器、变体契约、重试/日志、第二主题变体、`batch_accept.sh`、断点续跑、并行 worker、队列 UI、全量双跑；音频、序列帧、主题编辑器 UI、经济/商店。
批量能力留作后续 P2：等真有「一个项目出 N 条」的需求再加（单条链路已是脚本化的，包一层循环即可）。

## 执行方式

两 lane 并行、同题 PK：02_Game 与 03_Game_ds 各做一版，不合并代码、不互相改目录；两 lane 用同一套判据（tests / validate / simulate / render 确定性 + 可搬移 + 证据）；择优后未选中版本归档不删；分歧语义以择优结果写入规格 v0.22。
