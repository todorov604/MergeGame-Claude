## 附：调用 superpowers 的话术（学习版）

### 核心原则

superpowers 是"流程技能库"，不会自动生效。最有效的写法：

1. 开头点名**入口技能**（using-superpowers）；
2. 点名本任务需要的**具体流程技能**（不要只说"用 superpowers"）；
3. 写明"技能流程与任务约束冲突时，以本话术为准"。

### Claude（obra/superpowers，Claude Code / Desktop）

- 入口：Skill 工具调用 `superpowers:using-superpowers`
- 按任务挑：

| 场景 | 技能 |
|---|---|
| 修 bug / 未知行为 | `superpowers:systematic-debugging` |
| 写功能 / 修缺陷 | `superpowers:test-driven-development` |
| 多步骤实现 | `superpowers:writing-plans` + `superpowers:executing-plans` 或 `superpowers:subagent-driven-development` |
| 并行子任务 | `superpowers:dispatching-parallel-agents` |
| 完成前验证 | `superpowers:verification-before-completion` |
| 提交前自审 | `superpowers:requesting-code-review`（收到反馈用 `receiving-code-review`） |
| 分支收尾 | `superpowers:finishing-a-development-branch` |

- 一句话模板：

```text
开工前先调用 superpowers:using-superpowers；本任务是缺陷修复，按 superpowers:systematic-debugging 先复现，用 superpowers:test-driven-development 先写失败测试，用 superpowers:subagent-driven-development 组织子代理，收尾必须用 superpowers:verification-before-completion 验证后再声明完成。
```

### dsh（superpowers-dsh）

- 入口：`skill` 工具，裸名 `using-superpowers`
- 子技能同样是裸名：`systematic-debugging`、`test-driven-development`、`writing-plans`、`executing-plans`、`subagent-driven-development`、`dispatching-parallel-agents`、`verification-before-completion`、`requesting-code-review`、`receiving-code-review`、`finishing-a-development-branch`
- dsh 另有 `subagent` / `subagent_fork` / `workflow` 机制；superpowers-dsh 的 subagent-driven-development 就是围绕它们写的

```text
开工第一步用 skill 调用 using-superpowers；本任务是缺陷修复，按 systematic-debugging 复现、test-driven-development 先写失败回归、subagent-driven-development + dispatching-parallel-agents 并行子代理、verification-before-completion 验收后再报告完成。
```

### 常见误区

- 只说"请使用 superpowers" → 模型可能不加载具体技能；**点名技能最稳**。
- 前缀别写错：Claude 侧带 `superpowers:`；dsh 侧用裸名。
- 技能与你的硬约束冲突时，明确写"以本话术为准"。
- 让子代理干活时，在话术里直接给出**分工与文件边界**，比只说"多用子代理"有效得多。
